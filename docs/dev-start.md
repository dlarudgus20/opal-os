# 세션 복구 가이드

새 컴퓨터에서 저장소를 다시 열었을 때, 이전 작업 맥락을 빠르게 복구하기 위한 공식 절차입니다.

## Codex 시작 프롬프트
새 환경에서 Codex를 처음 켰을 때는 아래 프롬프트를 그대로 입력합니다.
이 프롬프트는 에이전트가 바로 작업을 시작하지 않고, 먼저 저장소 구조와 문서를 확인하도록 강제하기 위한 것입니다.

```text
이 저장소에서 작업 시작해줘. docs/dev-start.md 절차를 지침처럼 따라.
모든 응답은 한국어로.

먼저 코드를 수정하지 말고 저장소 구조 파악부터 해.
최소한 아래를 실제로 읽거나 검색한 뒤에 초기 보고를 해:
- AGENTS.md
- README.md
- docs/README.md
- docs/dev-start.md
- docs/build-system.md
- docs/testing.md
- docs/kernel-unit-test.md
- docs/opal/README.md 및 그 하위 문서 목록
- docs/libkc/README.md, docs/libcoll/README.md
- 각 서브프로젝트 README.md
- 루트 Makefile, mkfiles/conf.mk, mkfiles/rules.mk
- 주요 서브프로젝트 Makefile
- kernel/include, kernel/src, libkc/include, libkc/src, libcoll/include, libcoll/src의 큰 구조

가능하면 rg, find, ls, sed/nl 같은 읽기 전용 명령으로 구조를 확인해.
tmp/MEMORY.md가 있으면 한 번 읽되, 사실 여부는 코드/문서로 다시 검증해.

초기 보고에는 반드시 아래를 포함해:
1. 실제로 확인한 문서/코드 범위
2. 저장소 구조 요약
3. 빌드/테스트 흐름 요약
4. 현재 확인한 변경/위험/불확실성
5. 다음 액션 제안
```

## 원칙
- 1차 기준은 항상 코드/헤더/문서(`docs/`)입니다.
- 임시 메모(`tmp/MEMORY.md`)는 보조 힌트입니다.
- 코드와 메모가 충돌하면 코드를 우선합니다.

## 권장 시작 절차
1. 저장소 전반 탐색
   - 저장소 전체 코드와 `docs/`, `AGENTS.md`를 함께 훑어 전체 구조를 먼저 파악합니다.
   - 단순히 문서를 열었다고 보고하지 말고, 어떤 파일/디렉터리를 실제로 확인했는지 초기 보고에 남깁니다.
   - 코드 수정, 포맷팅, 정리 작업은 구조 파악과 초기 보고가 끝난 뒤에만 시작합니다.
2. 빌드/테스트 시스템 파악 및 기준선 확보
   - `Makefile`, `mkfiles/`, `docs/build-system.md`, `docs/testing.md`를 확인해 빌드 흐름을 먼저 파악합니다.
   - 이후 프로젝트 표준 검증 루틴(`make`, `make test`, `make unit-test` 및 관련 서브타깃)을 실행 가능한 범위에서 확인합니다.
3. 임시 메모 사용(있는 경우에만)
   - 사용자는 선택 사항으로 이전 context에 대한 메모를 `tmp/MEMORY.md` 파일로 제공할 수 있습니다.
   - `tmp/MEMORY.md`가 있으면 시작 시점에 1회 읽고, 유효/폐기 항목으로 분리합니다.
   - 분리 후에는 메모 재참조보다 코드 재확인을 우선합니다.
4. 다음 액션 계획 수립
   - 확인된 사실 기준으로 우선순위가 있는 다음 액션들을 정리합니다.

## 초기 보고 형식 (권장)
1. 확인 범위
   - 읽은 문서, 확인한 주요 디렉터리, 확인한 빌드 파일을 구분해 적습니다.
2. 현재 프로젝트 상태 요약(사실 기반)
   - 커널/라이브러리/도구/문서 구조를 함께 요약합니다.
3. 빌드/테스트 흐름
   - 기본 빌드, hosted 테스트, 커널 유닛테스트 명령과 주의점을 요약합니다.
4. `tmp/MEMORY.md` 유효 항목 / 폐기 항목 (`tmp/MEMORY.md`가 있을 때만)
5. 남은 불확실성/추가 확인 필요 사항
6. 다음 액션 제안(개수 제한 없음, 우선순위 포함 권장)

## 운영 팁
- `tmp/MEMORY.md`는 임시 파일입니다. 오래된 내용일 수 있으므로 신뢰하지 말고 검증하세요.
- 장기 보존할 정보는 `docs/` 또는 코드 주석으로 이동합니다.
- 복구가 끝난 뒤에는 임시 메모를 추가 사용하지 않는 것을 기본 방침으로 합니다.
  사용자는 복구가 끝난 뒤 언제든지 임시 메모를 삭제할 수 있습니다.
