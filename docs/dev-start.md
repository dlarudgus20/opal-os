# 세션 복구 가이드

새 컴퓨터에서 저장소를 다시 열었을 때, 이전 작업 맥락을 빠르게 복구하기 위한 공식 절차입니다.

## Codex 시작 프롬프트
새 환경에서 Codex를 처음 켰을 때는 아래 한 줄만 입력해도 됩니다.

```text
이 저장소에서 작업 시작해줘. docs/dev-start.md 참고해. 모든 응답은 한국어로.
```

## 원칙
- 1차 기준은 항상 코드/헤더/문서(`docs/`)입니다.
- 임시 메모(`tmp/MEMORY.md`)는 보조 힌트입니다.
- 코드와 메모가 충돌하면 코드를 우선합니다.

## 권장 시작 절차
1. 저장소 전반 탐색
   - 저장소 전체 코드와 `docs/`, `AGENTS.md`를 함께 훑어 전체 구조를 먼저 파악합니다.
2. 빌드/테스트 시스템 파악 및 기준선 확보
   - `Makefile`, `mkfiles/`, `docs/build-system.md`, `docs/testing.md`를 확인해 빌드 흐름을 먼저 파악합니다.
   - 이후 프로젝트 표준 검증 루틴(`make`, `make test`, `make unit-test` 및 관련 서브타깃)을 실행 가능한 범위에서 확인합니다.
3. 임시 메모 사용(있는 경우에만)
   - 사용자는 선택 사항으로 이전 context에 대한 메모를 `tmp/MEMORY.md` 파일로 제공할 수 있습니다.
   - `tmp/MEMORY.md`가 있으면 시작 시점에 1회 읽고, 유효/폐기 항목으로 분리합니다.
   - 분리 후에는 메모 재참조보다 코드 재확인을 우선합니다.
4. 다음 액션 계획 수립
   - 확인된 사실 기준으로 우선순위가 있는 다음 액션들을 정리합니다.

## 초기 보고 형식 (권장)
- 현재 프로젝트 상태 요약(사실 기반)
- `tmp/MEMORY.md` 유효 항목 / 폐기 항목 (`tmp/MEMORY.md`가 있을 때만)
- 남은 불확실성/추가 확인 필요 사항
- 다음 액션 제안(개수 제한 없음, 우선순위 포함 권장)

## 운영 팁
- `tmp/MEMORY.md`는 임시 파일입니다. 오래된 내용일 수 있으므로 신뢰하지 말고 검증하세요.
- 장기 보존할 정보는 `docs/` 또는 코드 주석으로 이동합니다.
- 복구가 끝난 뒤에는 임시 메모를 추가 사용하지 않는 것을 기본 방침으로 합니다.
  사용자는 복구가 끝난 뒤 언제든지 임시 메모를 삭제할 수 있습니다.
