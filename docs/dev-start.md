# 세션 복구 가이드

새 컴퓨터에서 저장소를 열거나 새 Codex 채팅에서 작업을 이어갈 때 사용합니다.

## Codex 시작 프롬프트

새 채팅에 아래 프롬프트를 넣고, 이어갈 작업이 있으면 마지막에 한두 문장으로 적습니다.

```text
이 저장소의 docs/dev-start.md를 따라 작업 맥락을 복구해줘. 응답은 한국어로 작성해.

먼저 저장소 루트, 워크트리, 브랜치, 미커밋 변경을 확인해. AGENTS.md와
관련 문서 및 빌드 규칙을 읽고, tmp/MEMORY.md가 있으면 현재 코드와 대조해.
탐색과 초기 보고가 끝날 때까지 소스나 설정은 수정하지 마.

확인한 작업 위치, 변경 상태, 빌드·테스트 경로, 아직 검증하지 못한 점을
짧게 보고해. 아래에 구체적인 작업을 적었다면 보고 후 그 작업을 이어가.
```

## 복구 절차

1. **작업 위치를 확인합니다.** 저장소 루트와 워크트리의 실제 경로, 현재 브랜치, 작업 트리 상태를 확인합니다. 여러 워크트리가 있으면 경로와 브랜치를 함께 대조합니다.

   ```bash
   git rev-parse --show-toplevel
   git worktree list
   git status --short --branch
   ```

   진행 중인 작업을 이어갈 때는 관련 파일의 `git diff`와 `git diff --cached`를 확인합니다. `git status`에 보이는 추적되지 않은 파일도 현재 상태에 포함합니다.

2. **작업에 필요한 문서와 코드를 읽습니다.** `AGENTS.md`에서 작업 지침을 확인하고, 루트 README와 문서 인덱스에서 저장소의 구조를 잡습니다. 빌드와 테스트를 확인할 때는 루트 `Makefile`, `mkfiles/config.mk`, `mkfiles/rules.mk`와 관련 서브프로젝트 Makefile을 대조합니다. 이어갈 작업이 정해져 있으면 해당 소스와 헤더부터 범위를 좁혀 확인합니다. [작업 지침](../AGENTS.md), [루트 README](../README.md), [문서 인덱스](README.md), [빌드 시스템](build-system.md), [커널 테스트](kernel-test.md)

3. **이전 세션의 메모를 대조합니다.** 사용자가 `tmp/MEMORY.md`에 남긴 메모가 있으면 시작할 때 읽습니다. 메모의 경로, 명령, 남은 작업을 현재 브랜치의 코드와 문서로 확인합니다. 현재 확인한 사실과 메모에만 남아 있는 내용은 초기 보고에서 구분합니다.

4. **초기 보고를 공유하고 필요한 검증을 진행합니다.** 작업 위치와 기존 변경, 확인한 빌드·테스트 경로를 먼저 공유합니다. 검증 범위는 이어갈 작업에 맞춥니다. 실행할 수 없는 명령은 도구나 환경에서 빠진 조건을 적습니다.

## 빌드·테스트 기준선

빌드 명령이 어떤 소스와 규칙을 사용하는지만 확인하려면 강제 dry-run을 사용합니다.

```bash
make -B -n build TEST=1
```

실제 검증이 필요하면 작업 범위에 맞춰 일반 빌드 또는 커널 테스트를 실행합니다. 여러 Make 실행이 같은 산출물을 건드리지 않도록 명령을 순차 실행합니다.

```bash
make build >/dev/null
make iso TEST=1 >/dev/null
make test QEMU_DISPNONE=1
```

QEMU는 테스트 결과를 출력한 뒤 자동으로 종료합니다. COM1 로그의 `==== test end ====` 요약과 `make test`의 종료 상태를 확인합니다. 결과를 공유할 때는 실제로 실행한 명령과 결과를 적습니다. [커널 테스트 실행 방법](kernel-test.md)
